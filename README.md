# SPC Playground

> 互動式統計製程管制 (SPC) 教學頁面 —— 以半導體**蝕刻製程**為情境。
> 純 HTML + vanilla JS，沒有任何外部相依、沒有建置步驟，打開 `index.html` 就能跑。

拉滑桿改變製程參數，管制圖、判異結果、Cp/Cpk 全部即時重算。目的不是做一套 SPC 系統，
而是把「UCL 是什麼」「為什麼要分組」「Cp 跟 Cpk 差在哪」從背名詞變成看得見的東西。

```bash
git clone https://github.com/<your-account>/spc-playground.git
cd spc-playground
python -m http.server 8000     # 或 npx http-server
# 打開 http://localhost:8000
node test/spc.test.js          # 跑統計核心的驗證
```

## 一分鐘版的 SPC

| 名詞 | 白話 |
|---|---|
| **CL** (Center Line) | 中心線，就是平均值 μ |
| **UCL / LCL** | 上／下管制界限 = **μ ± 3σ**。沒別的了 |
| **管制界限 vs 規格界限** | UCL/LCL 是**製程自己說的話**（它做得到什麼）；USL/LSL 是**客戶說的話**（它要什麼）。兩者毫無關係 |
| **共同原因 / 特殊原因** | 隨機雜訊 vs 有具體來源的異常。SPC 存在的唯一目的就是把這兩者分開 |
| **Cp** | 製程「夠不夠瘦」＝ 規格寬度 ÷ 6σ |
| **Cpk** | 製程「夠不夠瘦，而且有沒有偏」＝ 離最近那條規格有幾個 3σ |
| **失控 (OOC)** | Out Of Control。違反判異規則，不等於超出規格 |

最重要的一句：**管制圖抓的是「變化」，不是「超標」。** 全部都在規格內、卻連續 20 點都在中心線上方，
那是失控；全部都在管制界限內、但客戶規格很緊，那是能力不足。兩件事要分開講。

## 為什麼管制界限不是拿整體標準差算的

這是面試最容易問倒人的地方。

```
UCL = X̿ + A₂·R̄          其中 A₂ = 3 / (d₂·√n)
```

看起來很玄，其實還是 μ ± 3σ，只是 σ 換成用**組內全距 R̄** 去估：`σ̂ = R̄ / d₂`。

為什麼要這樣做？因為管制圖要偵測的就是「**組間**的變化」。
如果把組間的漂移也算進 σ，製程一偏移，σ 跟著變大，管制界限也跟著撐開 ——
等於拿犯人當尺去量犯人，永遠抓不到。用 R̄ 估的是**組內短期變異**，
那是乾淨的共同原因基準，才量得出組間跑掉多少。

頁面上的「凍結管制界限」勾選框展示的是同一件事的實務版本：
**Phase I** 先用一段穩定期建立界限，**Phase II** 拿這組界限去監控後續生產，而不是每來一筆就重算。

## 八條判異規則（Western Electric / Nelson Rules）

把管制圖從中心線往外切成 6 個區帶，各 1σ 寬，由內而外叫 C / B / A。

| # | 規則 | 抓的是 | 蝕刻現場的可能原因 |
|---|---|---|---|
| 1 | 1 點超出 3σ | 明顯異常 | RF 功率異常、流量計故障、錯放片 |
| 2 | 連續 9 點在中心線同側 | 平均偏移 | PM 後基準改變、換氣體鋼瓶、換 focus ring |
| 3 | 連續 6 點持續上升／下降 | 趨勢 | Chamber 壁沉積累積、化學液老化 |
| 4 | 連續 14 點上下交替 | 系統性交替 | 兩個 chamber 輪流跑卻畫在同一張圖 |
| 5 | 3 點中 2 點在同側 2σ 外 | 偏移早期警訊 | 溫控開始不穩 |
| 6 | 5 點中 4 點在同側 1σ 外 | 小幅持續偏移 | 氣體流量慢慢偏離設定 |
| 7 | 連續 15 點都在 1σ 內 | 資料「太漂亮」 | 量測解析度不足、界限算太寬、資料被修飾 |
| 8 | 連續 8 點都在 1σ 外 | 雙峰 | 兩台機台／兩種產品混流 |

一個實務細節，面試講出來會加分：**趨勢很少真的被規則 3 抓到**。
雜訊一大就很難連續 6 點嚴格遞增，實際上先響的通常是規則 2 和 6。
頁面上的「Chamber 沉積漂移」情境就是這樣。

## 內建的蝕刻異常情境

| 情境 | 物理原因 | 圖上的樣子 |
|---|---|---|
| 穩定製程 | 只有共同原因 | 沒有型態，什麼都別做 |
| Chamber 沉積漂移 | 腔壁聚合物累積 | 平均值一路往上爬 |
| PM 後階梯偏移 | 保養／換件後基準平移 | 整段抬高，變異不變 |
| 兩台機台混流 | A/B chamber 交替跑貨 | 規律鋸齒，中間帶被掏空 |
| 單片異常 | 一片晶圓量測暴衝 | **X̄ 圖毫無反應，只有 R 圖爆掉** |
| 片內均勻度變差 | 電漿／溫度分佈不均 | X̄ 圖還好，R 圖整段抬高 |
| 製程改善後 | 變異縮小但界限沒更新 | 全擠在 1σ 內 → 觸發規則 7 |

「單片異常」那個情境是整個專案最想傳達的一件事：
**X̄ 圖要配 R 圖看，而且要先看 R 圖。** R 圖失控代表 R̄ 不可信，
那 X̄ 圖的管制界限本身就是錯的，看了也沒意義。

## Cp / Cpk

```
Cp  = (USL − LSL) / 6σ                       夠不夠瘦
Cpk = min( (USL−μ)/3σ , (μ−LSL)/3σ )         夠不夠瘦 + 有沒有偏
```

`Cpk ≤ Cp` 恆成立，兩者的差距就是偏移量。所以：

- **Cp 高、Cpk 低** → 製程本身夠好，只是偏掉了 → 把中心拉回來（調 recipe／校正）
- **Cp 也低** → 變異本身太大 → 要做的是降低變異，調中心沒用

| Cpk | σ 水準 | 不良率 | 意義 |
|---|---|---|---|
| 1.00 | 3σ | ~2,700 ppm | 太危險 |
| 1.33 | 4σ | ~63 ppm | 業界常見量產門檻 |
| 1.67 | 5σ | ~0.6 ppm | 良好 |
| 2.00 | 6σ | ~0.002 ppm | 「六標準差」（考慮 1.5σ 長期偏移後就是那個著名的 3.4 ppm） |

**Pp / Ppk** 公式一模一樣，只是 σ 改用整體樣本標準差（長期，含組間漂移）。
`Cpk 遠大於 Ppk` ⇒ 短期很穩但長期一直漂 ⇒ 該去查漂移的原因。

## 專案結構

```
index.html            主頁（所有版面與說明文字）
src/spc.js            統計核心：係數表、管制界限、八條判異規則、Cp/Cpk（無相依，Node 也能 require）
src/chart.js          手刻 SVG 繪圖，沒有圖表函式庫
src/scenarios.js      蝕刻異常情境的資料產生器
src/app.js            互動與狀態
test/spc.test.js      核心計算驗證（不用測試框架，node 直接跑）
tools/build-artifact.js  打包成單檔 dist/artifact.html
```

`src/spc.js` 刻意寫成可獨立使用：

```js
const SPC = require('./src/spc.js');

const subgroups = [[10,12,11,9,13], [11,11,12,10,11], /* ... */];
const stats = SPC.analyze(subgroups);            // n=1 會自動切成 I-MR
const hits  = SPC.detectViolations(stats.primary.values,
                                   stats.primary.CL,
                                   stats.primary.sigma);
const cap   = SPC.capability(100, stats.sigmaWithin, 96, 104);  // → { cp, cpk, ppm, ... }
```

測試涵蓋：X̄-R 與 I-MR 的界限公式、八條規則各自的正反例、穩定製程的誤報率、
Cp/Cpk 與 ppm 的對應（1.33 → 63 ppm、1.00 → 2700 ppm）。
