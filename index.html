SPC Playground

把統計製程管制 (Statistical Process Control) 從「背名詞」變成「看得見」。 所有圖都是即時算的：拉滑桿改變製程，管制圖就跟著動。以蝕刻製程為例。

1先把已知的接上未知的

你已經懂常態分佈跟 3 個標準差。管制圖其實就是把那張鐘形圖轉 90 度，然後在時間軸上一直畫點。

UCL / LCL 就是 μ ± 3σ。沒別的了。 Upper / Lower Control Limit ＝ 上／下管制界限。點落在裡面 = 只有隨機波動； 點落在外面 = 機率只有 0.27%，與其相信「這麼衰」，不如相信「製程真的變了」。

左邊那條鐘形曲線和右邊的點是同一份資料。把 3σ 那條線往右拉成一整條水平線，就是 UCL。

2製程模擬器

先選一個情境，再拉滑桿感受每個參數對管制圖的影響。

紅實線 = UCL / LCL（μ ± 3σ） 綠虛線 = CL 中心線（平均值） 灰色橫帶 = A/B/C 區，每帶 1σ 寬 黑點 = 正常 紅點 = 被判異，上方數字是違反的規則編號 左側曲線 = 同一份資料的常態分佈 滑鼠停在點上可看該點的數值與 z 值

上圖 X̄＝每組的平均值，看「製程中心有沒有跑掉」。 下圖 R＝每組的最大值減最小值，看「同一組內的變異有沒有變大」。 兩張圖看的是不同的事，缺一不可。

管制界限是怎麼算出來的？（點開看實際數字）

現場不用整體標準差，而是用「組內全距 R̄」去估 σ。 因為組內變異＝製程的短期雜訊（純的共同原因），把它拿來當尺，才量得出組間的偏移。 用整體 σ 算界限是新手最常犯的錯：製程一偏移，整體 σ 跟著變大，界限也跟著撐開，結果永遠抓不到失控。

5Cp / Cpk：管制界限 ≠ 規格界限

  
這是最常被混淆的地方，先記這句：
     UCL/LCL 是製程自己說的話（它做得到什麼），USL/LSL 是客戶說的話（它要什麼）。
     兩者完全無關，Cp/Cpk 就是在比這兩件事差多少。


  

    

      
      
    

    

      
      
    

  


  

  

  


  

    
指標一句話講清楚公式

    
Cp製程「夠不夠瘦」。規格寬度能塞下幾個 6σ。

        完全不管製程有沒有偏掉 —— 就算整批都做在規格外，Cp 還是可以很漂亮。		
        (USL−LSL) / 6σ

    
Cpk製程「夠不夠瘦，而且有沒有偏」。看離最近那條規格還有幾個 3σ。

        Cpk ≤ Cp 恆成立。兩者差距就是偏移量。		
        min( (USL−μ)/3σ , (μ−LSL)/3σ )

    
Pp/Ppk同樣的公式，但 σ 改用整體樣本標準差（長期，含組間漂移）。

        Cpk 遠大於 Ppk ⇒ 製程短期很穩，但長期一直漂 ⇒ 去查漂移的原因。		
        σ 改用 s（整體）

  







  
6面試速查：常見追問


  
管制圖失控了，你第一件事做什麼？
    
先確認「是製程真的變了，還是量測／記錄出錯」。依序：查量測系統 → 查是否有事件（PM、換件、換料、換機台）→ 看型態屬於哪一類（偏移／趨勢／變異變大／混流）→ 才動製程。
    切忌看到一點超標就調 recipe，那會把共同原因當特殊原因處理，反而讓變異變大。


  
為什麼管制界限用 R̄ 算，不直接用整體標準差？
    
因為管制圖要偵測的就是「組間的變化」。如果把組間的漂移也算進 σ，界限會被撐寬，漂移就永遠抓不到 —— 等於拿犯人當尺量犯人。
    R̄/d₂ 估的是組內短期變異，是乾淨的共同原因基準。


  
Cpk 1.33 是什麼概念？
    
1.33 = 製程中心離最近規格有 4σ，雙邊不良率約 63 ppm，是業界最常見的量產放行門檻。
    1.00 = 3σ，約 2700 ppm，太危險。1.67 = 5σ，約 0.6 ppm。所謂「六標準差」指的是 Cpk 2.0（考慮 1.5σ 長期偏移後就是那個著名的 3.4 ppm）。


  
X̄ 圖和 R 圖要先看哪一張？
    
先看 R 圖。因為 X̄ 圖的管制界限是用 R̄ 算的 —— R 圖若失控，代表 R̄ 本身不可信，X̄ 圖的界限就是錯的，看了也沒意義。
    先把變異穩住，再談平均值。試試上面的「單片異常」情境：X̄ 圖幾乎沒反應，R 圖直接爆掉。


  
n 越大越好嗎？
    
n 越大，組平均的標準差 σ/√n 越小，管制界限越窄，越能抓到小偏移（靈敏度高）。但量測成本也越高，而且界限太窄會頻繁誤報 (false alarm)。
    現場常見 n=3~5。半導體很多量測很貴，只能 n=1，那就改用 I-MR 圖 —— 把上面的 n 拉到 1 看看圖會怎麼變。


  
SPC 跟 APC / R2R 有什麼不同？
    
SPC 是監控：告訴你製程有沒有變，變了叫人來看。APC（Advanced Process Control）／R2R（Run-to-Run）是回饋控制：自動依上一批的量測結果調整下一批的 recipe。
    兩者並存 —— 但要注意 R2R 會把漂移「補掉」，讓管制圖上看起來很平，所以有 R2R 的機台通常還要額外監控「控制器補償量」本身。這題答得出來會很加分。
